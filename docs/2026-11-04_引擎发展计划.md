# 记忆引擎发展计划（2026-11-04）

## 1. 定位

记忆引擎不是“再训一个模型”，而是三层能力：

1. **数据层**：episodes / segments / workflows，负责记什么、怎么查
2. **策略层**：floor、k、subject 分仓、去重、出处、A/B，负责怎么召回
3. **模型层**：7B adapter / Qwen / GLM teacher，负责怎么判、怎么生成

当前最强的是数据层，最需要补的是策略层，模型层受 8GB 显存约束。

- 备份：`work/memory/backups/`，保留 14 份

## 3. 三层路线

### 3.1 数据层
- 保持 append-only；写入口唯一
- 新事件必须带 outcome / provenance / actor
- 段摘要与 episode 的 subject 一致性作为硬门禁
- 目标：检索命中带出处 100%

### 3.2 策略层（当前重点）
- 查询集：10 条固定 + 每周新增 10 条真实查询
- 指标：hit_rate、diversity、provenance、subject_ok、avg_hits、latency
- 扫参：floor ∈ {0.05,0.10,0.15,0.20}，k ∈ {3,5,8}
- 晋级：总分不低于现役，且 subject_ok=1.0
- 回滚：`strategy_state.json` 保留 history，旧配置可恢复

### 3.3 模型层
- Ollama Qwen 做 teacher/judge/data generator（推理，不训练）
- 7B QLoRA 只在小样本、显存 ≥6.5GB 时跑
- GLM-5.3-Flash 只做低频独立审核（ZCode UI）
- 任何候选 adapter 不覆盖现役，先 candidate/shadow

## 4. Harness 闭环

```
任务 → 结构化召回（k/floor/subject）
     → 执行
     → 结果回写（episode）
     → promote/compact
     → 训练/评测样本
     → 策略或 adapter 候选
     → eval 门禁
     → 晋级/回滚
```

原则：召回是 harness 义务，不是 prompt 建议；失败 fail-open，不拦业务。

## 5. 阶段目标

### 2 周
- 策略评测每周自动跑一次
- 训练页可解释“为什么没训”
- 恢复演练通过

### 4 周
- Qwen judge 评测集 ≥50 条
- 至少一次 7B QLoRA 小样本 candidate
- ZCode 独立审核 ≥1 份

### 8 周
- candidate/shadow/rejected 完整晋级链
- 官方兼容端点适配
- 召回指标周报

## 6. 验收指标

- 体检全绿
- duplicate=0
- subject mismatch=0
- provenance=100%
- recall hit_rate ≥0.9，diversity ≥0.8
- 训练/策略变更 100% 可回滚
- 任何晋级都有 eval 报告与备份

## 7. 不做

- 不训练托管 GLM-5.3-Flash
- 不在 6.0GB 显存下强启 7B 训练
- 不让候选覆盖现役
- 不做无人审批的自动晋级
