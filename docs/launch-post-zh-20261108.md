# 我做了一个让 AI 不敢乱点 Windows 的闸

> 副标题：Windows 桌面 Agent 的默认拒绝、动作验证和证据链<br>
> 发布前替换：`{{DEMO_VIDEO}}`、`{{RELEASE_URL}}`、`{{INSTALL_CMD}}`

## 先说结论

AI 已经能在 Windows 上点按钮、打字、切窗口。<br>
但真正难的不是“让它能点”，是**让它点错之前停下来，点完之后能证明发生了什么**。

我做了一个开源项目：**computer-use-gate**。

一句话：

> **AI 不点头不动手；点错能拦；动完能验；事后能回放。**

它不是又一个 Computer Use 框架，而是 Windows 桌面 Agent 的**安全闸 + 可验证执行层**。

## AI 操作桌面，最危险的不是不会点

如果你真的让 Agent 操作过 Windows，你会遇到这三类问题：

1. **点错窗口**：它以为自己在点记事本，实际点到了别的窗口。
2. **假成功**：动作发出去了，但界面根本没变，它却说“完成了”。
3. **查不到**：出问题后，你不知道它点了什么、为什么点、前后画面是什么。

大多数 demo 只展示“能点”，不展示“点错了怎么办”。<br>
computer-use-gate 反过来：**默认拒绝，先过闸，再动手，动完验证。**

## 它到底做了什么

### 1. 默认拒绝

装完什么都不动。<br>
Agent 要动手，必须由**你本人**在屏幕弹窗输入授权密钥、点“授权”。一张通行证管 30 分钟或 60 个动作。

### 2. 五道闸

- 通行证：AI 不能偷偷动手
- 租约：同一时间只有一个 Agent 能碰键鼠
- 帧凭据：不能拿旧截图点新画面
- 敏感窗口：授权/密码类窗口直接拦
- 急停：`Ctrl+Alt+Home` 一键全停

### 3. 五条视觉通道，不需要显卡

- UI Automation：直接读控件名/类型/位置
- Windows OCR：系统自带，不下载模型
- 浏览器 CDP：网页 DOM
- 图标字体反查：Segoe 码点模板匹配
- 视觉模型：默认关闭，只在以上都认不出时兜底

原则：**能问 Windows 要结构化答案的，绝不看像素；能看像素解决的，绝不请模型。**

### 4. 动作后验证

动作发出去不算成功。<br>
每个动作做完再看一眼屏幕，只给三种判词：

- 生效
- 确认没变
- 没测出来

后两者都不算成功。

### 5. 证据链

前后截图 + 哈希链日志 + 可回放视频。<br>
改过一个字，`ctl_verify` 能指出从第几条开始坏。

## 它不做什么

- 不做无人值守批量点击
- 不绕过验证码/风控
- 不支持 Linux/macOS
- 不适合需要 SLA 的生产环境（0.x 实验版）
- Canvas、游戏、PDF 内嵌渲染、没开无障碍的 Electron 可能读不到控件

## 为什么开源

因为“AI 能不能操作桌面”不是某一家公司的问题。<br>
Windows 桌面 Agent 会越来越多，但**权限、审计、回滚**这一层不该每个项目自己造一遍。

computer-use-gate 想做的，是这一层：

> **别人让 Agent 能动手；我们让动作可控、可验、可回放。**
