## 1. P0：把“能用”变成“可重复”

### 1.1 记忆保留与恢复
- `backup` 每日自动 + 手动；保留 14 份
- 恢复演练：从备份启动只读查询，校验 episodes/segments 计数与 integrity
- 验收：恢复后 `quick_check=ok`，召回 10 条查询全部有出处

### 1.2 训练前置检查透明化
- 训练页显示 GPU 显存、Ollama 驻留模型、episodes 增量、距上次成功天数
- 预检失败标“跳过”，不标“失败”
- 验收：训练页能解释“为什么这一轮没训”

### 1.3 策略评测闭环
- `python -m agentctl.memory tune` 产出 `strategy_state.json`
- 循环读取 `best.k/floor`，重启生效
- 验收：至少一次 k/floor 变更 + 前后 recall 指标对比

## 2. P1：训练与评测自动化

### 2.1 Qwen teacher/judge
- 用 Ollama `qwen2.5:7b` 批量生成/判定
- 所有样本带 `source / outcome / provenance`
- 失败重试、超时、JSON 解析失败降级

### 2.2 7B QLoRA 小样本
- 显存 ≥ 6.5GB 才启动
- 候选进入 `candidate/`，不覆盖现役
- eval 不低于现役 -3 分才晋级
- 失败进入 `rejected/`，保留证据

### 2.3 GLM-5.3-Flash 独立审核
- 通过 ZCode UI 低频调用（agentctl）
- 弹“切换免费额度”时选切换
- 只做审核/种子，不做高频批量
- 验收：至少一份独立审核意见带出处

## 3. P2：自进化与官方接壤

- candidate/shadow/rejected 三目录 + 晋级/回滚
- 官方 OpenAI/Anthropic 兼容端点适配
- Agent 调用路径统一：OpenCode/ZCode/DSH/VSCode → ctl_memory/MCP
- 观测：召回命中率、多样性、出处率、延迟、成本

## 5. 风险

- 8GB GPU 与 Ollama 驻留冲突：训练前必须 `ollama stop`
- GLM UI 自动化受登录/额度弹窗影响：只做低频
- 训练数据量与拒答/幻觉门禁仍是硬约束
- 任何策略/权重变更必须可回滚
